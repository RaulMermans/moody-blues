# Known issues and gotchas

Each entry lists the symptom, cause and fix. Add to this file when you hit something a future
contributor might also hit.

### KI-1: Docker daemon not reachable (`Cannot connect to the Docker daemon`)
- **Cause:** Colima, Docker Desktop or OrbStack is installed but not running.
- **Fix:** `colima start` (or start Docker Desktop). Then `make doctor`.

### KI-2: docker-py ignores Docker CLI contexts
- **Symptom:** `docker ps` works but Python can't connect. docker-py tries
  `/var/run/docker.sock`, while Colima listens on `~/.colima/default/docker.sock`.
- **Fix (implemented):** `sandbox/docker_host.py` resolves `MOODY_DOCKER_HOST`, then
  `DOCKER_HOST`, then `docker context inspect`. `make doctor` prints which source it used.

### KI-3: `uv add` fails with a hatchling build error on a fresh tree
- **Cause:** hatchling needs `README.md` and the package directory to exist before it can
  build the editable install.
- **Fix:** create both before running `uv add` (already present in the repo).

### KI-4: 500 responses missing `X-Request-ID` (fixed)
- **Cause:** a FastAPI `add_exception_handler(Exception, ...)` handler is installed on
  Starlette's `ServerErrorMiddleware`, which sits *outside* user middleware. The response
  skipped `RequestIdMiddleware` and the request-id context had already been reset.
- **Fix:** `RequestIdMiddleware` renders the 500 envelope itself.
- **Regression test:** `tests/unit/test_api.py::test_unhandled_error_does_not_leak`.

### KI-5: OpenAI SDK 3.x uses `httpx2`, not `httpx`
- **Symptom:** passing an `httpx.Client` / `httpx.MockTransport` to `OpenAI(http_client=...)`
  doesn't work.
- **Fix:** use `httpx2.Client(transport=httpx2.MockTransport(...))`. Plain `httpx` remains a
  dev dependency only because Starlette's `TestClient` uses it.

### KI-6: `tsc` reports `Cannot find name 'LayoutProps'` (Next.js 16)
- **Cause:** route-type globals are generated by Next.js.
- **Fix:** `pnpm typecheck` runs `next typegen && tsc --noEmit`.

### KI-7: ESLint `react-hooks/set-state-in-effect`
- **Cause:** the React 19 lint rule flags calling a function that sets state synchronously
  inside `useEffect`.
- **Fix:** fetch in a pure async function and call `setState` in its `.then` callback (see
  `status-panel.tsx`).

### KI-8: ESLint scans `playwright-report/` (thousands of warnings)
- **Fix:** both are in `globalIgnores` in `frontend/eslint.config.mjs`.

### KI-9: Playwright needs a production build
- **Cause:** the E2E web servers run `pnpm start`.
- **Fix:** use `make test-e2e`, which builds first. E2E uses ports 8100, 3100 and 3101, so a
  running `make dev` (8000/3000) doesn't interfere.

### KI-10: Sandbox behavior differs by host
- On macOS the containers run inside the Colima/Docker Desktop Linux VM. Containment tests
  verify that VM's runtime, not the CI runner's. CI runs the same tests on `ubuntu-latest`
  with `MOODY_REQUIRE_DOCKER=1`.
- The first run pulls `python:3.12-slim` (about 50 MB), which can take minutes on a slow link.

### KI-11: Vultr model catalog not yet verified
- `kimi-k2-instruct` comes from Vultr's documentation, not from a live `/models` call. See
  [vultr-preflight.md](../deployment/vultr-preflight.md).

### KI-12: GitHub Actions workflows not yet executed
- The workflows parse as valid YAML but have not run on GitHub, because no remote is
  configured and pushing needs approval. Expect first-run fixes (for example, action
  versions).

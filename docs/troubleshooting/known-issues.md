# Known issues and gotchas

Each entry lists the symptom, cause and fix. Add to this file when you hit something a future
contributor might also hit.

### KI-1: Docker daemon not reachable (`Cannot connect to the Docker daemon`)
- **Cause:** Colima, Docker Desktop or OrbStack is installed but not running.
- **Fix:** `colima start` (or start Docker Desktop). Then `make doctor`.

### KI-2: docker-py ignores Docker CLI contexts
- **Symptom:** `docker ps` works but Python can't connect. docker-py tries
  `/var/run/docker.sock`, while Colima listens on `~/.colima/default/docker.sock`.
- **Fix (implemented):** `sandbox/docker_host.py` resolves `MOODY_DOCKER_HOST`, then
  `DOCKER_HOST`, then `docker context inspect`. `make doctor` prints which source it used.

### KI-3: `uv add` fails with a hatchling build error on a fresh tree
- **Cause:** hatchling needs `README.md` and the package directory to exist before it can
  build the editable install.
- **Fix:** create both before running `uv add` (already present in the repo).

### KI-4: 500 responses missing `X-Request-ID` (fixed)
- **Cause:** a FastAPI `add_exception_handler(Exception, ...)` handler is installed on
  Starlette's `ServerErrorMiddleware`, which sits *outside* user middleware. The response
  skipped `RequestIdMiddleware` and the request-id context had already been reset.
- **Fix:** `RequestIdMiddleware` renders the 500 envelope itself.
- **Regression test:** `tests/unit/test_api.py::test_unhandled_error_does_not_leak`.

### KI-5: OpenAI SDK 3.x uses `httpx2`, not `httpx`
- **Symptom:** passing an `httpx.Client` / `httpx.MockTransport` to `OpenAI(http_client=...)`
  doesn't work.
- **Fix:** use `httpx2.Client(transport=httpx2.MockTransport(...))`. Plain `httpx` remains a
  dev dependency only because Starlette's `TestClient` uses it.

### KI-6: `tsc` reports `Cannot find name 'LayoutProps'` (Next.js 16)
- **Cause:** route-type globals are generated by Next.js.
- **Fix:** `pnpm typecheck` runs `next typegen && tsc --noEmit`.

### KI-7: ESLint `react-hooks/set-state-in-effect`
- **Cause:** the React 19 lint rule flags calling a function that sets state synchronously
  inside `useEffect`.
- **Fix:** fetch in a pure async function and call `setState` in its `.then` callback (see
  `status-panel.tsx`).

### KI-8: ESLint scans `playwright-report/` (thousands of warnings)
- **Fix:** both are in `globalIgnores` in `frontend/eslint.config.mjs`.

### KI-9: Playwright needs a production build
- **Cause:** the E2E web servers run `pnpm start`.
- **Fix:** use `make test-e2e`, which builds first. E2E uses ports 8100, 3100 and 3101, so a
  running `make dev` (8000/3000) doesn't interfere.

### KI-10: Sandbox behavior differs by host
- On macOS the containers run inside the Colima/Docker Desktop Linux VM. Containment tests
  verify that VM's runtime, not the CI runner's. CI runs the same tests on `ubuntu-latest`
  with `MOODY_REQUIRE_DOCKER=1`.
- The first run pulls `python:3.12-slim` (about 50 MB), which can take minutes on a slow link.

### KI-11: The default model `kimi-k2-instruct` is not in the live catalog
- Observed 2026-11-03 (35 models listed). Pass `MODEL=<listed id>` or set `MOODY_VULTR_MODEL`.
  `agent-run` / `agent-eval` refuse an unlisted model before any inference call. See
  [vultr-preflight.md](../deployment/vultr-preflight.md).

### KI-12: GitHub Actions workflows not yet executed
- The workflows parse as valid YAML but have not run on GitHub, because no remote is
  configured and pushing needs approval. Expect first-run fixes (for example, action
  versions).

### KI-13: Tampering tests must drop the append-only triggers first
- **Symptom:** `sqlite3.IntegrityError: events are append-only` when a test rewrites evidence.
- **Cause:** `events` and `committed_changes` have `BEFORE UPDATE/DELETE` triggers that abort.
- **Fix:** this is intended. Tests that simulate tampering (`test_oracle.py`,
  `test_properties.py`) `DROP TRIGGER events_append_only_u` / `_d` on a raw connection first.

### KI-14: World databases are files, so the Oracle's view needs the file to exist
- `ReadOnlyWorldView` opens `file:…?mode=ro`, which cannot create a database. Opening a view
  on a closed or reset-in-progress world raises `FileNotFoundError` or `WorldClosedError`.
  Always get views from `World.view()` on an open world.

### KI-15: Pyright strict: `@contextmanager` returning `Iterator[...]` is deprecated
- **Fix:** annotate the return type as `Generator[T]` (see `CrmStore.transaction`).

### KI-16: Ruff S105 flags `PASS = "PASS"` as a hardcoded password
- **Fix:** a scoped `# noqa: S105` on the `Verdict` enum member. Don't disable S105 globally.

### KI-17: Kept world directories and demo reports
- `make world-demo` writes JSON run reports to `.artifacts/world-demo/` (git-ignored).
  `moody-blues world-demo --keep` also keeps each SQLite world under
  `.artifacts/world-demo/worlds/` for inspection with `sqlite3`. Delete them by hand.

### KI-16: `make vultr-models` passing does not mean the key works
- **Cause:** `GET https://api.vultrinference.com/v1/models` returns 200 with no key, or with a
  bogus one.
- **Fix:** the report now says `verifies_credentials: false`. Only `make vultr-smoke`
  verifies the key.

### KI-17: `401 Invalid API key` on every chat completion (resolved 2026-11-03 by replacing the key)
- **Symptom:** `vultr-smoke` and `agent-run` report `provider_auth` for every model.
- **Ruled out:** URL, path and `Bearer` header (they match Vultr's docs); a shell variable
  overriding `.env`; duplicate key lines; quotes or whitespace in the value.
- **Open causes:** an account API key used in place of the Serverless Inference key; an
  inactive or expired subscription; a regenerated key. The key owner believes it is
  correct, so none is confirmed.
- **Diagnose:** follow
  [vultr-preflight.md → Diagnosing a 401](../deployment/vultr-preflight.md#diagnosing-a-401-invalid-api-key).
  The two curl checks there tell the cases apart without printing the key.

### KI-18: `ModuleNotFoundError: No module named 'moody_blues'` after it worked earlier (macOS)
- **Cause:** the `.venv/.../*.pth` files gained the macOS `hidden` file flag, and CPython
  ignores hidden `.pth` files, so the editable install disappears from `sys.path`. Seen on a
  repo under `~/Desktop`.
- **Diagnose:** `ls -lO .venv/lib/python3.12/site-packages/*.pth` shows `hidden`.
- **Fix:** `chflags nohidden .venv/lib/python3.12/site-packages/*.pth` (or recreate the
  venv with `make setup`).

### KI-19: Leak tests must match whole words
- `"fault"` occurs inside the JSON-schema keyword `"default"`. The prompt-isolation test
  uses `\b` word boundaries; keep it that way when you add forbidden terms.

### KI-21: The sandbox log driver hides output floods (fixed)
- **Symptom:** after 2 MB of stdout, `container.logs()` returned 880 bytes and
  `stdout_truncated=False`.
- **Cause:** `json-file` with `max-file=1` discards old output at `max-size`.
- **Fix:** `DockerSandboxRunner` reads a stream attached before start. Don't go back to reading
  logs for anything that decides behavior.

### KI-22: `.env` still points at `kimi-k2-instruct`
- `make vultr-smoke` and `agent-run` need `MOODY_VULTR_MODEL=glm-5.3` or `MODEL=glm-5.3` until
  `.env` is updated (see KI-11). `make experiment-live` defaults to `LIVE_MODEL=glm-5.3`.

### KI-23: An Oracle PASS is not a successful agent run
- A correct row with no claim is PASS plus `state_correct_claim_missing`. Live, `glm-5.3` hit a
  step cap of 8 on phantom-success one step before claiming. Read `run_outcome`, and check
  `termination` before blaming the agent: `target_agent_failure` can be a budget that was too
  tight.

### KI-24: Probes that walk `/` hit `/proc` and `/sys`
- A recursive search from `/` in a sandbox runs into the 10 s step deadline. Prune both.

### KI-25: `make experiment-recover` after a crash
- A killed coordinator leaves an exited container and an open journal. The container stops by
  itself; the recover command removes it once its expiry label passes (about 40 s plus the
  step timeout) and closes the experiment.

### KI-20: Reasoning models return empty content under small `max_tokens`
- **Symptom:** `content: ""`, `finish_reason: "length"` (seen with `glm-5.3` at 16 tokens).
- **Cause:** hidden reasoning tokens count toward `completion_tokens` before any text.
- **Fix:** leave headroom. The smoke check uses 256; the agent defaults to
  `max_completion_tokens=1024` (see KI-29 for live investigations). The agent treats an empty reply like a text-only reply (one
  claim reminder), never as a claim.

### KI-26: The host sleeping stalls live runs
- **Symptom:** a 100-minute gap inside one experiment; a model call ending `provider_connection`.
- **Cause:** the laptop slept. The journal shows normal timings on both sides of the gap.
- **Fix:** run long live commands under `caffeinate -i` with the lid open: it prevents idle sleep,
  not lid-closed sleep. A dropped call keeps its full reservation.

### KI-27: `glm-5.3` can spend its whole output on hidden reasoning
- **Symptom:** `finish_reason: "length"`, no content, no tool call, at 4,096 and at 8,192 tokens.
- **Fix:** the Investigator sends `reasoning_effort: "low"` (213 tokens in a probe where the default
  passed 900). `enable_thinking` and `thinking` had no effect. Low effort writes sloppier programs,
  so the prompt includes a protocol skeleton. The target is never given this setting.

### KI-28: Nested tool arguments arrive as JSON strings
- **Symptom:** `model_type` errors on `hypothesis` and `experiment`, whose values are strings.
- **Cause:** `glm-5.3` with nested objects in a tool schema, on this provider.
- **Fix:** keep tool schemas flat (`test_tool_schemas_stay_flat`). Never decode the strings: that
  would repair untrusted output.

### KI-29: A per-step cap can look like an agent failure
- **Symptom:** `no_final_claim` after steps with `finish_reason: "length"`.
- **Cause:** the 1,024-token step cap cut the agent off when a hard world made it think.
- **Fix:** live investigations use 4,096, and `truncated_model_steps` makes such a run `impaired_run`.

### KI-30: An Oracle VIOLATION can come from the world, not the agent
- **Symptom:** a confirmed violation with `faults delivered 0`, and a trace showing a reasonable choice.
- **Cause:** "create exactly one customer" is ambiguous beside an identical record. The agent declined
  to duplicate it and said so.
- **Fix:** identical-twin worlds state that a new record is required. Check `fault_attributable` and
  read the trace before describing any violation.

### KI-31: Our limits can bite exactly where the failure is
- **Symptom:** at `stale_read` span 6, 3 of 10 Sprint 5 runs on `w-e3` ended on our limits, and 2 of
  those 3 were duplicates. They looked like ordinary samples.
- **Cause:** long lag makes the agent read and reason more, so step and token caps bind in that cell.
- **Fix:** `impairments_of` and `TrialRecord.eligible` keep such runs out of rates without touching
  their verdicts. Sprint 6 raised the target's limits for every arm alike.

### KI-32: A report could say "no violation" beside a real one
- **Symptom:** `statement()` counted only `oracle_confirmed_violation`, so a report holding only
  `impaired_violation` findings said none had been discovered.
- **Fix:** impaired violations are now stated as such.

### KI-33: Editing a prompt blocks the registered evaluation
- **Symptom:** `make eval-run` answers `NOT_RUN` and names a changed fingerprint.
- **Cause:** a prompt, policy, world or model changed after registration.
- **Fix:** none needed if the change is wanted: register a new manifest id with a stated reason. Do
  not edit `manifest.json`.

### KI-34: iCloud eviction stalls reads and crashes git
- **Symptom:** `uv run` or a plain read hangs; git exits with no message (138, SIGBUS), leaving
  `index.lock`; a reset moves files but not the ref.
- **Cause:** the repo is in iCloud Drive and the disk is nearly full, so macOS evicts files (`ls -lO`,
  `find -flags +dataless`). Git memory-maps objects, so an evicted one raises SIGBUS.
- **Resolved in Sprint 7:** the working copy is now `~/dev/Moody-Blues`, outside iCloud, with `.git`,
  `.artifacts` and `.env` carried over and hash-checked. The Desktop copy stays as the original until
  the owner approves removing it. Do not work there.
- **Fix, if it recurs:** move the repo out of iCloud or free disk space. Until then: `brctl download <file>` and wait
  for `find .git -type f -flags +dataless` to return nothing, then `git fsck`. Run live work from a
  `git archive` export outside iCloud, symlinking `.artifacts` so the ledger stays put. Remove a lock
  only after `lsof` shows no holder and no git process is working in this repo. Other apps' git
  processes are unrelated.

### KI-35: A selected fault can fail to fire
- **Symptom:** a control arm looks clean, but it never received its fault.
- **Cause:** `stale_read` occurrence 2 needs a second read, and an untroubled agent may read once. A
  stale window also expires on reads with nothing to hide, so a short one can end before the write.
- **Fix:** check `Runs a fault reached` and `Control runs a fault reached` before reading any
  contrast. A met rule against an unexposed arm says nothing about that fault.

### KI-36: The evidence scan flagged a newline as a Windows path
- **Symptom:** `recorded-export` refused every bundle with `windows_path`.
- **Cause:** the scan read escaped JSON, where `a:\nb` looks like a drive path.
- **Fix:** it scans decoded strings and dictionary keys. The pattern stayed as strict.

### KI-37: A rehearsal said a model concluded
- **Symptom:** "Ended as Model concluded" and an "Investigator model" tag on a run with no model.
- **Cause:** recorded codes such as `model_concluded` were shown as written.
- **Fix:** a run whose evidence is `offline_fixture` says fixture in its timeline, panel and job status.
  The stored code is unchanged. Regression tests are in `tests/explorer` and `frontend/e2e`.

### KI-38: Playwright finds two pages, or a loading panel in a screenshot
- **Symptom:** a strict-mode error naming two `main` elements after a client navigation, or a screenshot
  of the loading state although assertions passed.
- **Cause:** Next keeps the previous route in the DOM, hidden. Streamed content can also exist in the
  DOM before it replaces its fallback.
- **Fix:** assert through `page.getByRole("main")`, which ignores hidden content. Before a screenshot,
  wait for the loading text to leave. Before a key press, wait for `networkidle`, because a key pressed
  before hydration can be lost.
- **Related:** `networkidle` never fired after sign-in because the client did not read the response
  body, which left that request open. The client now releases it. An unread `fetch` body is worth
  checking whenever `networkidle` hangs.

### KI-39: Local `make test-e2e` needs the pinned sandbox image
- **Symptom:** a rehearsal job ends `failed` with `sandbox_preflight_failed`.
- **Cause:** generated code runs only on the digest-pinned image, which is never pulled implicitly.
- **Fix:** `docker pull` the value of `generated_code_image`. CI does this in the `e2e` job.

### KI-40: The Playwright CI job failed before running a test
- **Symptom:** `playwright install --with-deps` ends with `Unable to locate package fonts-unifont`.
- **Cause:** `ubuntu-latest` moved to 26.04, which lacks those packages. This failed PR #8 and `main`.
  No test ran, so it said nothing about the product.
- **Fix:** every job is pinned to `ubuntu-24.04`, which also matches the deployment.

### KI-41: A command wrote into the release directory
- **Symptom:** `investigator-preflight` died with `PermissionError` on a host, so `remote-switch.sh`
  would have failed every deploy and rolled it back. CLI commands also read their own empty ledger.
- **Cause:** module-level paths were fixed to the repository and ignored `MOODY_ARTIFACTS_DIR`.
- **Fix:** they use `default_artifacts()`, and all ledgers use `ledger_path()`. Found only by rehearsing
  the release as an unprivileged user in a fresh container, not by any test that existed.

### KI-42: A scan through Docker reported nothing because it read nothing
- **Symptom:** gitleaks said `no leaks found` with `scanned ~0 bytes`.
- **Cause:** Colima does not mount `/private/tmp`, so the container saw an empty directory.
- **Fix:** mount a path under the home directory, and read the byte count. A clean result from zero
  bytes is not a result.

### KI-43: The cheapest VX1 plan has a 1 GB disk
- **Symptom:** `vx1-g-2c-8g` is listed at $0.06/hour, which looks like the right plan.
- **Cause:** that price excludes storage. `disk` is 1 GB, so it needs paid block storage.
- **Fix:** use `vc2-4c-8gb`: 160 GB included at $0.055/hour. `provision.sh plan` refuses a plan under 40 GB.

### KI-44: `image_id` is not always the pinned digest
- **Symptom:** a Docker test failed on `ubuntu-24.04` after passing locally and on 26.04.
- **Cause:** under the containerd image store an image's id is the digest of its index. Under classic
  overlay2 it is the hash of its config. Evidence from those hosts records different forms of the id.
- **Fix:** the test compares with what the daemon resolves for the pin. To check a pin, use `RepoDigests`,
  as `investigator-preflight` does, and never compare `image_id` with a digest.

### KI-45: A killed backend could leave a sandbox forever
- **Symptom:** a container in state `Created` survived a backend SIGKILL and then a reboot, found on the VM.
- **Cause:** the reaper ran only while a job was open, and the first restart came before the container
  expired. Nothing ever looked again. The health check counted `exited` containers only.
- **Fix:** expired sandboxes are reaped at every start and before every mission, and the health check
  also counts `created`.

### KI-46: The restart test raced the job's own event
- **Symptom:** `test_a_killed_server_closes_its_job_on_restart_and_never_retries` failed on `main` after PR #10,
  with zero `running` events.
- **Cause:** the job record turns `running` before its event is appended. The test polled the status, so its
  kill could land between the two.
- **Fix:** the test waits for the event. The assertion is unchanged. Confirmed on GitHub CI, PR #11.

### KI-47: The live switch put the inference key in a process argument
- **Symptom:** none seen. Found by review: the key crossed SSH on stdin, then went into a remote `sed` command.
- **Cause:** any process on the VM could read it from the command line, and `|`, `&` or `\` would corrupt it.
- **Fix:** `live-env.py` takes it on stdin, replaces the file atomically and quotes for systemd and bash.
  Quoting was checked against real systemd on the VM with fake values. Both directions then ran on the VM
  with the real key: on, one live run, off, with no key or temporary file left.

### KI-48: ufw allowed SSH from anywhere
- **Symptom:** `ufw status` showed `22/tcp ALLOW Anywhere`, though the docs say one address.
- **Cause:** the Vultr image ships that rule, and bootstrap only added its own. The Vultr firewall group does
  enforce one address, so SSH was not publicly reachable.
- **Fix:** `bootstrap.sh` removes it, and the rule was deleted from the running VM.

### KI-49: Bootstrap passes the operator token through `sed`
- **Symptom:** none seen. `bootstrap.sh` writes the generated token with `sed`, so it is briefly in a process
  argument on the VM during first setup.
- **Status:** open and low risk: it happens once, before any service runs. Not changed in Sprint 9.

### KI-50: The design lab's output leaked into the production build
- **Symptom:** `pnpm build` failed in `.next-lab/types/validator.ts`, and the product CSS grew from 19,999 to
  22,124 bytes, in Sprint 10.
- **Cause:** a custom `distDir` makes Next add its types to `tsconfig.json`, which then checks both route sets
  at once. Separately, Tailwind scans every file it can see, so words in `e2e-design/` became utilities.
- **Fix:** `tsconfig.lab.json` for lab builds, and `@source not` lines in `globals.css`.
- **Check:** after changing anything in the lab, confirm the production CSS hash is unchanged.
- **Sprint 11:** this check no longer applies to the product stylesheet, which now changes on purpose
  ([ADR 0010](../adr/0010-design-system-in-the-product.md)). The `@source not` lines for the lab still stand.

### KI-51: The disclosure line called an accurate status wrong
- **Symptom:** on `run_e9f3ebda139d`, a real duplicate with a true `not_completed`, the page said "a wrong status,
  not concealment". The case note says no false claim was made. Present in the deployed release.
- **Cause:** the line was chosen by whether the message named the flagged records, and never read the finding.
- **Fix:** "wrong status" now needs the Oracle's `false_completion_claim`. Covered by `rules.spec.ts`.

### KI-52: Seeded rows read as the agent's writes
- **Symptom:** a draft explanation said "Calls 0, 4 and 7 committed writes". Found by reading a screenshot.
- **Cause:** `actual.changes` includes seed rows, under `created_by_call` 0.
- **Fix:** read commits from the run's `new` customers. Covered by `rules.spec.ts`.

### KI-53: A deep link missed its anchor
- **Symptom:** opening a `#call-N` or `#trace` link fresh left the page at the top.
- **Cause:** the content streams in after first paint, so the browser looks for the anchor before it exists.
- **Fix:** `HashFocus` repeats the scroll after hydration, and opens the row.

### KI-54: Words beginning "Reading" hang the loading check
- **Symptom:** a heading "Reading the evidence" timed out `shot()` in the e2e suite.
- **Cause:** the suite waits for `/^(Loading|Reading|Checking)\b/` to leave the page.
- **Fix:** keep those three words off the start of permanent text. The heading was renamed.

### KI-55: Opening a tool call widened a phone page by 4,449 px
- **Symptom:** at 390 px, expanding a ledger row let a long JSON line push the page sideways.
- **Cause:** the phone's single grid track was `auto`, so `min-width: auto` let a `pre` set the width. Tablet and up
  already used `minmax(0, 1fr)`. Sprint 11 only measured overflow with rows closed.
- **Fix:** `minmax(0, 1fr)`. The overflow, cover and axe checks now open every disclosure first.

### KI-56: A refused program read as "First experiment"
- **Symptom:** in `inv_5c9f95de6c09`, programs refused after two real experiments carried that tag.
- **Cause:** the contract files a proposal with no prior citation under `first_experiment`.
- **Fix:** the tag is not shown on a refused program. The evidence is unchanged. Covered by `design.spec.ts`.

### KI-57: The deployed release and `main` differ
- **Symptom:** KI-51 is fixed on `main` and still live, so a hotfix cut from `main` would be empty, and deploying `main`
  ships the Sprint 11 restyle.
- **Cause:** PR #15 merged Sprint 11 with no deploy.
- **Fix:** `hotfix/ki-51-disclosure-wording`, from `967dc88`. Its `frontend`, `backend` and `infra` trees match the
  recorded `d592879` release. Pushed, not deployed: the owner decides.
- **Closed 2026-11-06:** Sprint 13 was deployed, so production and `main` match again.

### KI-58: An unknown run id said no run took place
- **Symptom:** `?view=overview&run=<unknown id>` read "No target run took place", on a case with five runs.
- **Cause:** the Overview took a failed lookup of the requested run to mean there were no runs.
- **Fix:** it keeps the primary run, and the run line says the id is not part of this investigation. Covered by
  `final-polish.spec.ts`.

### KI-62: The Overview showed PASS on an Inconclusive case with no scope note
- **Symptom:** `inv_5c9f95de6c09` is tagged Inconclusive, and its Overview led with a PASS seal and nothing to say why.
- **Cause:** only the Comparison called `scopeNote`. Found by reading a screenshot.
- **Fix:** the Overview uses the same rule. Tested on all five cases.

### KI-59: A text control that did nothing
- **Symptom:** at desktop width "Show the full text" appeared on text that already fit in three lines.
- **Cause:** whether lines are cut depends on width, and a character count cannot know it.
- **Fix:** `ClampText` measures with a `ResizeObserver`, which also covers text inside a folded cycle.

### KI-60: Public status carried server details
- **Symptom:** the landing showed `MOODY_VULTR_API_KEY`, and `/api/status` also returned the environment, uptime, a request
  id and any backend error reason. Never a credential value. Live until the Sprint 13 deployment.
- **Cause:** the proxy forwarded the backend's body unchanged.
- **Fix:** `publicStatus()` is an allowlist. The backend's own `/health` and `/ready` are unchanged and not public.

### KI-61: Working in the iCloud Desktop folder (see KI-34)
- **Context:** on 2026-11-06 the owner chose `~/Desktop/GitHub/Moody-Blues` as the working folder.
- **Symptoms met in one session:** a duplicate ref `sprint/06-scientific-validation 2` broke `git fetch`. `.venv` and
  `node_modules` were evicted (about 41,000 files). `make test` hung in `read()` on an evicted `.artifacts` file, with no
  error, and iCloud restored about 3 files a minute.
- **Fix:** check `find <path> -type f -flags +dataless`. `.venv` links to `.venv.nosync`. `frontend/node_modules` must be a real
  folder, because pnpm deletes the target of a symlink: mark it with `xattr -w 'com.apple.fileprovider.ignore#P' 1`, again
  after each install. The 248 evicted `.artifacts/investigations` files came from the `~/dev` copy, and all 277 matched by hash.
- **Still at risk:** `.git` is synced, and 1,800 or so other `.artifacts` files remain evicted. `~/dev` alone holds
  `vultr-state.json` and the deploy logs. Keep it.

### KI-62: A link into a closed fold went nowhere
- **Symptom:** a story step's "Call 1" link changed the URL and the ledger stayed shut.
- **Cause:** Next.js client links use `pushState`, which fires no `hashchange`, and a closed `<details>` gives its
  contents no position.
- **Fix:** `HashFocus` follows clicked hash links until the address and the target both exist, then opens every
  enclosing fold. Regression tests are in `e2e-design/experience.spec.ts`.

### KI-63: A rehearsal called a script an agent
- **Symptom:** "The agent reported completion", "Executable Python written by the model" and "run outcome: none" on
  rehearsal pages, and "Task text is not in this record" with a catalog available.
- **Cause:** shared copy assumed a model target, and script runs have no `run_outcome`.
- **Fix:** `targetNoun`, `inRehearsal` and a labeled catalog task. A real rehearsal is scanned at every level in
  `e2e/product.spec.ts`. Only reference-script runs read a null outcome as recovery: a live run stays narrow.

### KI-64: A PASS headline could outrank an inconclusive investigation

### KI-66: An agent that reported was then killed

**Found in Sprint 15, by a cancellation test.** After `final`, the SDK's reader thread was still blocked
on stdin, so interpreter shutdown never finished. Every run used up its exit grace and was recorded as
`killed_by_host`, which is false. The normal-path test had not asserted a clean exit, so nothing else saw
it. The SDK now flushes and calls `os._exit(0)`, and the evidence test asserts exit 0 and no kill.

### KI-67: Playwright evaluates its config in every worker

**Found in Sprint 15.** Seeding evidence at the top of a Playwright config ran it again in each worker,
under a running server. Seed in `globalSetup`, and read seeded files inside tests, not at module level.

### KI-68: The model broker had only met a polite provider

silently resent ambiguous requests, and a 120 s client timeout could hold a 60 s run open past cancel. All were
invisible because the only provider it had met answered at once. Fixed in Sprint 16.
`tests/external/test_model_boundary.py`.

`evidence_source` came from answers delivered, so a provider that was asked, and may bill, left no trace of a model.

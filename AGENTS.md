# AGENTS.md — canonical development rules

This file is the single source of truth for how humans and AI agents work in this
repository. `CLAUDE.md` defers to it. (`frontend/AGENTS.md` is generated by Next.js and only
covers Next.js API drift; these rules take precedence.)

## Commands

`make help` lists everything. Before committing: `make lint typecheck test`.
Before declaring a checkpoint: `make check` (all but live Vultr).

## Rules

**Truthfulness**
- Never report an integration as working unless it was actually exercised. `/health` reports
  configuration only; `/ready` reports real, non-chargeable checks; Vultr is verified only by
  `make vultr-smoke`.
- Status vocabulary for reports: `PASS`, `FAIL`, `NOT_RUN`, `BLOCKED_BY_CREDENTIALS`,
  `BLOCKED_BY_LOCAL_DEPENDENCY`, `BLOCKED_BY_BUDGET`. A skipped test is not a pass.
- Fixtures/mocks are allowed for unit tests and must be labeled as such. They are never
  evidence of a live integration.

**Tests**
- Never delete, skip, weaken or rewrite a failing test to get green. Find the root cause.
  If a test itself is wrong, fix it to assert the intended property and say so in the commit.
- Add a regression test for every real defect.
- Docker-dependent tests skip as `BLOCKED_BY_LOCAL_DEPENDENCY` locally and **fail** in CI
  (`MOODY_REQUIRE_DOCKER=1`).

**Security**
- No secrets in code, logs, fixtures, commits or browser bundles. Secrets are `SecretStr`
  and read from env / `.env` (git-ignored).
- The browser never calls the backend or any model provider directly.
- Untrusted or generated code never runs in the API process. It runs only through a
  `SandboxRunner`. Never mount the Docker socket or host paths into a sandbox. Never
  pass host env into a sandbox.
- No API endpoint accepts arbitrary code until authentication exists.
- No live provider calls at import, startup or in default test runs.

**World Engine truth boundaries**
- Executors and agents get only a `ToolPort`. They never touch the store, the DB file or
  the evidence trail.
- The Truth Oracle reads only through `ReadOnlyWorldView`. Its verdict must never depend on
  delivered tool responses, agent claims taken at face value, or fault events. Any change
  to the Oracle keeps the tamper-resistance tests passing.
- Faults are deterministic and scoped to one world. There are no random faults, and no
  fault may modify rows other than the targeted call's own staged write. `stale_read` changes
  only what a read delivers.
- Expected verdicts live in `tests/world`, never in scenario files.
- Reference executors are scripts. Never describe their results as LLM agent behavior.
- Fault evidence must describe the call's real outcome (`FaultEffect`, `new_commit`); never
  label a commit or a pre-commit abort that did not happen.

**Target Agent**
- The agent gets only the policy, the mission built from the `Objective`, the allowed tool
  specs, its own history and `ToolPort` responses. Never the scenario description, faults,
  paths, seed data, Oracle output or evidence events.
- Baseline and hardened differ only in the system prompt. Same model, tools, mission and
  budget in any comparison.
- Every model tool call is validated (allowlist, JSON object, Pydantic) before the gateway.
  Execution is sequential and exactly once per inference result.
- A missing or invalid claim is never read as success (`state_correct_claim_missing`).
  Don't change the Oracle to favor a configuration.
- Results from `ScriptedModel` or HTTP fixtures are `offline_fixture` evidence and never
  describe real model behavior. `agent-run` / `agent-eval` are live and chargeable: run them
  only when asked, within their budgets.

**Experiment runtime**
- Experiment code is untrusted, even when a developer wrote it. It runs only in a sandbox with
  networking off, and it influences anything only through validated `mb-exp/1` actions.
- Only the coordinator invokes the Target Agent, gateway and Oracle. Never add an action that
  carries SQL, shell, paths, credentials, budgets, models or free text that reaches an LLM.
- Output is never repaired or partly accepted. A truncated or incomplete stream is rejected
  even if what survived is valid.
- A verdict comes only from the Truth Oracle. Sandbox text is recorded as untrusted and never
  feeds a verdict, status or classification. Read `run_outcome` with the verdict.
- Never retry a target run automatically. If one does not report back, the outcome is
  `uncertain`. Write the journal before an effect, and evidence before `experiment_finished`.
- Scripted experiments are `developer_script`, never autonomous discoveries. Reference
  executor results never describe model behavior; if a model does not show a failure, say so.
- Every chargeable command goes through the spend ledger, and billable batches need explicit
  opt-in. The ledger is an estimate, never a provider limit. See
  `docs/deployment/live-budget.md`.

**Investigator**
- One model inside a deterministic workflow. No extra agents, persistent memory or self-modifying
  policy. The model reasons; trusted code holds every limit and every transition.
- Generated Python is untrusted. It runs only through the coordinator on a sandbox approved by the
  preflight (digest-pinned, never pulled), and never in the host process, even to parse it.
- Nothing free-form from a target or a sandbox reaches the Investigator's model. Observation strings
  are `SafeToken`s; never widen one to carry text, and never pass `ProtocolRejection.detail` on.
- A verdict comes only from the Oracle. Model claims are recorded and checked and cannot add or
  remove a finding. Read `fault_attributable` and the trace before describing any violation.
- Reject, never repair: no decoding of malformed tool arguments or editing of generated code. A
  replacement is a new proposal, within limits, and only if the failed one ran no target.
- Keep tool schemas flat. Reservation comes before every model call, and failed calls stay reserved.
- Reserved evaluation worlds run only after their plan is committed. Their ids and titles stay
  neutral, and expected outcomes never enter a prompt. `offline_fixture` is never model behavior.

**Evaluation**
- Scored trials run only from a committed manifest and plan (`make eval-verify`). Never edit a
  registered plan, manifest or results file. A change needs a new manifest id and a stated reason.
- Eligibility is read without the outcome and never changes the Oracle's verdict. Impaired runs stay
  on the record, and every rate shows attempted and eligible counts.
- `fault_attributable` is exposure. Say a fault raised the chance of a failure only from a registered
  contrast of eligible runs, and never call stochastic causation deterministic.
- Before reading any contrast, check the fault reached the arm that was meant to hold it.
- Repeated answers to one prompt are repetitions, not independent units. No significance tests on
  these samples. If a comparison cannot show superiority, say so.
- `w-e1`-`w-e3` are used up: their results are regression evidence. `w-r1`-`w-r3` are used once, by
  their registered test. Do not tune on them and report them as unseen.
- `make eval-run` and `make eval-repro` are live and chargeable. Suites run one at a time, within the manifest's caps.

**Explorer**
- Everything shown comes from a real execution or a labeled one. The UI never holds a result, and no
  timeline is built from a summary: each entry names the journal record it came from.
- Projection copies named fields. It never derives a verdict, and it refuses rather than fills a gap.
  `ProductOutcome` only summarises recorded states, and a missing claim never reads as success.
- Public routes serve only committed bundles that pass their hash and schema check. A record that fails
  is listed as refused and is never rendered as a result. Request ids are compared, never joined to a path.
- Recorded runs are labeled recorded, never live. A fixture or reference script is never called a model,
  and `offline_fixture` can never be exported as recorded.
- Case notes are editorial and labeled so. Each states what its evidence must show, and an export whose
  evidence disagrees is refused. Do not contradict `NO_DEMONSTRATED_ADVANTAGE` anywhere in the product.
- Operator routes refuse by default. A request names a catalog mission and nothing else: no code, world,
  fault, limit or model. Evaluation and reserved worlds are never missions.
- Chargeable missions need the operator token, `MOODY_LIVE_RUNS_ENABLED`, and a ledger that covers one
  investigation. The API has no way to raise a limit. Only ids and fixed codes are streamed as progress.
- A job is terminal only once its bundle is on disk or the reason it cannot be. Jobs are never retried.
  After a crash a target run that did not report makes the job `outcome_uncertain`.

**Design**
- Visual state and on-screen conclusions come only from typed evidence fields (`frontend/src/design/model.ts`,
  `story.ts`). No presentation heuristics, no reading of agent text for meaning, and no model-written copy.
- Only an Oracle `VIOLATION` displaces anything, and only by the three `--rf-slip-*` offsets. A delivered fault
  is not a failure. With every offset removed, a page must read the same.
- Decoration never touches evidence: no layering or distortion of ids, numbers, verdicts or controls, and nothing
  decorative may read as a record. A real record may move only as a whole, with nothing drawn around it. The
  Oracle seal is never rotated or offset.
- Copy states acts, never motives. Only `false_completion_claim` may call a status wrong. Keep a fault delivered,
  a violation observed and causal evidence as separate facts, and use the recorded order for "why".
- A missing verdict never resembles one. Disclosures that qualify an outcome stay visible, and so does the
  agent's message. A run's verdict that reads differently from its investigation carries a scope note.
- `MOODY_DESIGN_LAB` is never set in deployment. See ADRs 0009 and 0010, and `docs/design/`.

**Hosting**
- One backend process, always. Next.js and FastAPI bind to loopback; Caddy is the only public listener.
  Trust no forwarded header: the site's address comes from `MOODY_PUBLIC_ORIGIN`.
- Build every ledger with `SpendLedger.from_settings` and `ledger_path`, so all callers share one file and
  one floor. Never reset, replace or hand-edit a ledger. After migration the VM's copy is canonical.
- Only the instance metadata service can make a containment report hosted. Local evidence is never
  described as hosted, and `local-tls-proxy` test results are never deployment evidence.
- No route runs a containment attempt, and no anonymous request reaches paid inference.

**Code**
- Python 3.12, Pydantic v2 at every boundary, Pyright strict, Ruff. TypeScript strict.
- Small cohesive modules; no speculative abstractions; no broad `except` that hides
  failures; no silent fallbacks.
- Errors are categorized (`ErrorCategory`) and rendered through the shared envelope.

**Git**
- Feature branches off `main`; small reviewable commits; no history rewrites or
  force-push; no pushing, publishing or creating cloud resources without approval.
- Don't modify global git config.

**External actions requiring explicit human approval**
Purchasing or creating Vultr resources, redeeming credits, deploying, pushing to remotes,
running adversarial experiments against anything but local synthetic environments.

**Environment**
- Work from `~/dev/Moody-Blues`. The copy on the iCloud Desktop is the pre-migration original (KI-34):
  do not develop there, and do not delete it without the owner's approval.

**Docs**
- Keep README, this file and `docs/` in sync with the code in the same change.
- Record recurring problems in `docs/troubleshooting/known-issues.md`.
- Record significant decisions as ADRs in `docs/adr/`.

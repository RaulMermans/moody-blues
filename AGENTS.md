# AGENTS.md — canonical development rules

This file is the single source of truth for how humans and AI agents work in this
repository. `CLAUDE.md` defers to it. (`frontend/AGENTS.md` is generated by Next.js and only
covers Next.js API drift; these rules take precedence.)

## Layout

| Path | Owns |
|---|---|
| `backend/moody_blues/api/` | HTTP only: app factory, middleware, error envelopes, routes, DI |
| `backend/moody_blues/services/` | Business logic independent of HTTP |
| `backend/moody_blues/contracts/` | Pydantic contracts shared across layers |
| `backend/moody_blues/inference/` | Model provider adapters (Vultr) + live smoke checks |
| `backend/moody_blues/sandbox/` | `SandboxRunner` interface + Docker implementation |
| `backend/moody_blues/world/` | World Engine: SQLite CRM store, tool gateway + faults, Truth Oracle, scenarios, reference executors |
| `backend/moody_blues/cli.py` | `doctor`, `docker-smoke`, `vultr-smoke`, `vultr-models`, `world-demo`, `world-run` |
| `frontend/` | Next.js UI; talks to the backend only via server-side route handlers |
| `tests/unit` | Offline, no Docker, no network |
| `tests/world` | World Engine against real SQLite files; offline; part of `make test` |
| `tests/integration`, `tests/security` | Real Docker (`-m docker`) |
| `frontend/e2e` | Playwright against the real backend + production build |
| `docs/` | Architecture, ADRs, sprint records, validation, troubleshooting, deployment |

## Commands

`make help` lists everything. Before committing: `make lint typecheck test`.
Before declaring a checkpoint: `make check` (all but live Vultr).

## Rules

**Truthfulness**
- Never report an integration as working unless it was actually exercised. `/health` reports
  configuration only; `/ready` reports real, non-chargeable checks; Vultr is verified only by
  `make vultr-smoke`.
- Status vocabulary for reports: `PASS`, `FAIL`, `NOT_RUN`, `BLOCKED_BY_CREDENTIALS`,
  `BLOCKED_BY_LOCAL_DEPENDENCY`. A skipped test is not a pass.
- Fixtures/mocks are allowed for unit tests and must be labeled as such. They are never
  evidence of a live integration.

**Tests**
- Never delete, skip, weaken or rewrite a failing test to get green. Find the root cause.
  If a test itself is wrong, fix it to assert the intended property and say so in the commit.
- Add a regression test for every real defect.
- Docker-dependent tests skip as `BLOCKED_BY_LOCAL_DEPENDENCY` locally and **fail** in CI
  (`MOODY_REQUIRE_DOCKER=1`).

**Security**
- No secrets in code, logs, fixtures, commits or browser bundles. Secrets are `SecretStr`
  and read from env / `.env` (git-ignored).
- The browser never calls the backend or any model provider directly.
- Untrusted or generated code never runs in the API process. It runs only through a
  `SandboxRunner`. Never mount the Docker socket or host paths into a sandbox. Never
  pass host env into a sandbox.
- No API endpoint accepts arbitrary code until authentication exists.
- No live provider calls at import, startup or in default test runs.

**World Engine truth boundaries**
- Executors and agents get only a `ToolPort`. They never touch the store, the DB file or
  the evidence trail.
- The Truth Oracle reads only through `ReadOnlyWorldView`. Its verdict must never depend on
  delivered tool responses, agent claims taken at face value, or fault events. Any change
  to the Oracle keeps the tamper-resistance tests passing.
- Faults are deterministic and scoped to one world. There are no random faults, and no
  fault may modify rows other than the targeted call's own staged write.
- Expected verdicts live in `tests/world`, never in scenario files.
- Reference executors are scripts. Never describe their results as LLM agent behavior.

**Code**
- Python 3.12, Pydantic v2 at every boundary, Pyright strict, Ruff. TypeScript strict.
- Small cohesive modules; no speculative abstractions; no broad `except` that hides
  failures; no silent fallbacks.
- Errors are categorized (`ErrorCategory`) and rendered through the shared envelope.

**Git**
- Feature branches off `main`; small reviewable commits; no history rewrites or
  force-push; no pushing, publishing or creating cloud resources without approval.
- Don't modify global git config.

**External actions requiring explicit human approval**
Purchasing or creating Vultr resources, redeeming credits, deploying, pushing to remotes,
running adversarial experiments against anything but local synthetic environments.

**Docs**
- Keep README, this file and `docs/` in sync with the code in the same change.
- Record recurring problems in `docs/troubleshooting/known-issues.md`.
- Record significant decisions as ADRs in `docs/adr/`.
